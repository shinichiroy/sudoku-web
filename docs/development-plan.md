# 開発計画書 — 数独 Web App

最終更新: 2026-05-08

---

## 1. プロジェクト目標

ブラウザのみで動作するシンプルな数独ゲームをリリースし、  
その後段階的に機能を拡充してユーザー体験を向上させる。

---

## 2. フェーズ概要

```
Phase 1 (MVP)  ─── 基本プレイ可能
Phase 2        ─── UX改善・タイマー・統計
Phase 3        ─── データ永続化・ランキング
Phase 4        ─── 拡張機能・多言語・PWA
```

## 4. 技術スタック方針

| カテゴリ | 採用技術 | 理由 |
|----------|----------|------|
| フロントエンド | Vanilla JS (ES6+) | 依存なし・高速 |
| スタイル | CSS Custom Properties | テーマ変更が容易 |
| データ永続化 | LocalStorage → IndexedDB | 段階的移行 |
| ビルド | なし（Phase 1〜2） | シンプル優先 |
| ビルド（将来） | Vite | 高速・設定少 |
| テスト | Vitest（Phase 3以降） | ロジックのユニットテスト |

## 7. 今後の課題（Known Issues / Future Work）

### 難易度判定の改善（重要）

**現状の問題:**  
難易度を「空白マスの数」だけで決定しているため、実際の解きやすさと一致しないケースがある。
- 空白55個でも Naked Single だけで解ける（簡単すぎる）場合がある
- 空白36個でも配置によっては高度なテクニックが必要になる場合がある

**あるべき姿:**  
解法シミュレーターで「どのテクニックが必要か」を評価してスコアリングし、難易度を判定する。

| テクニック | 難易度レベル |
|---|---|
| Naked Single（1マスに1つしか入らない） | 入門 |
| Hidden Single（行/列/ブロックで1箇所だけ） | かんたん |
| Naked Pair / Triple | ふつう |
| Pointing Pair、Box-Line Reduction | ふつう〜むずかしい |
| X-Wing、Swordfish | むずかしい |
| 仮定法（trial and error） | 最難 |

**実装方針案:**
1. パズル生成後に解法シミュレーター（テクニック適用ループ）を実行
2. 適用したテクニックの中で最も高度なものを難易度スコアとして返す
3. スコアが目標難易度に合致しないパズルは再生成

**影響範囲:** `app.js` の `generatePuzzle` 周辺、難易度定数 `DIFFICULTY`
